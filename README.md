# 集群资源热力图数据服务

本仓库实现了一套集群资源热力图的数据服务，把逐节点采样按时间窗口聚合成可查询的热力图视图。整条链路只在本进程内运行，不依赖任何外部服务，结论可在本地稳定复现。

## 核心特性

- **确定性窗口聚合**：支持可配置的时间窗口与滑动步长，窗口边界与单元归属确定。相同输入在任何到达顺序与任何并发度下产出的单元逐条一致。
- **水位策略**：支持迟到、乱序与重复到达的采样。迟到不被静默丢弃，重复不计入两次。按既定水位策略决定窗口何时封口，封口前后状态可区分。
- **修订与补算**：支持对已封口窗口的迟到补算与修订，修订可追溯并带版本。补算结果与用全量数据直接聚合的结果一致，不出现只改一部分字段的中间状态。
- **多维度下钻查询**：支持按节点、节点池、资源类型与时间范围等条件下钻查询。任一层级的聚合结果与底层单元自洽，跨窗口与跨维度合并不重复计数或漏计。
- **并发安全**：聚合与查询并发进行，任一时刻查询到的是某个已提交的完整视图，不出现窗口级或字段级的混合状态。慢查询不阻塞聚合推进。
- **资源上界与背压**：采样速率超过处理能力时内存与待处理队列不无界增长。达到上界时行为确定且可观测。
- **持久化与重启恢复**：已封口窗口及其修订记录在重启后完整还原，未封口的中间状态与聚合进度可区分，恢复过程不重复计入或丢失采样。

## 窗口语义

### 翻滚窗口（Tumbling）

当窗口大小等于滑动步长（`WindowSize == WindowSlide`）时，每个采样恰好归属一个窗口。窗口边界按固定原点（Unix 纪元）对齐，例如 `[10:00, 10:01)`、`[10:01, 10:02)`。

### 滑动窗口（Sliding）

当滑动步长小于窗口大小（`WindowSlide < WindowSize`）时，每个采样归属多个重叠窗口。例如窗口大小为 60s、滑动步长为 20s 时，每个采样归属 3 个窗口。窗口边界同样按固定原点对齐。

窗口归属判定：窗口 `[start, start+size)` 包含事件时间 `t` 当且仅当 `start <= t < start+size`。

### 确定性

窗口边界由事件时间与固定原点唯一确定，与到达顺序无关。因此相同输入在任何到达顺序下产出的窗口归属一致。

## 水位策略

水位线（Watermark）定义为：

```
watermark = maxEventTime - allowedLateness
```

其中 `maxEventTime` 是已观测到的最大事件时间，`allowedLateness` 是允许的迟到时间。

### 封口时机

当窗口结束时间 `windowEnd <= watermark` 时，该窗口被封口。封口后窗口状态从开放（open）变为已封口（sealed）。

### 迟到数据

- **乱序数据**：事件时间小于 `maxEventTime` 但窗口仍开放，正常聚合。
- **迟到数据**：事件时间对应的窗口已封口，触发修订（revision）。
- **重复数据**：`(NodeID, Seq)` 已存在，不计入两次。

### 封口前后状态区分

- 开放窗口：状态保存在内存中，可继续聚合。
- 已封口窗口：状态固化为单元（Cell），默认不可变，除非修订。

## 修订规则

当迟到数据到达已封口窗口时，触发修订：

1. 加载该窗口已有的单元。
2. 将迟到数据作为贡献单元（count=1, sum=value, min=max=value）。
3. 合并两个单元（count/sum 相加，min 取小，max 取大）。
4. 版本号递增。
5. 记录修订日志（旧版本、新版本、触发样本、时间戳）。
6. 原子提交新视图。

### 可追溯性

每次修订记录包含：
- 窗口起始时间
- 节点 ID 与资源类型
- 旧版本号与新版本号
- 触发修订的样本标识
- 修订时间戳

### 补算一致性

补算结果与用全量数据直接聚合的结果一致。这是因为汇总统计是可分配的：count/sum 可加，min 取小，max 取大。合并已有单元与迟到贡献等价于聚合所有原始样本。

### 原子性

修订在锁内完成，新视图通过原子指针发布。查询要么看到旧的完整视图，要么看到新的完整视图，不出现中间状态。

## 配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `WindowSize` | 窗口大小 | 1 分钟 |
| `WindowSlide` | 滑动步长 | 1 分钟 |
| `AllowedLateness` | 允许的迟到时间 | 10 秒 |
| `MaxOpenWindows` | 最大开放窗口数（超过则强制封口） | 1000 |
| `MaxSeen` | 最大已见样本标识数（超过则清理旧条目） | 100000 |
| `QueueCapacity` | 有界队列容量 | 1024 |
| `DropPolicy` | 队列满时的策略（Block/Drop） | Block |
| `WALPath` | 预写日志路径 | 空（不持久化） |
| `SnapshotPath` | 快照路径 | 空（不持久化） |

## API 概览

```go
// 创建服务
cfg := heatmap.DefaultConfig()
svc, _ := heatmap.NewService(cfg)
svc.Start()
defer svc.Stop()

// 提交样本
svc.Submit(sample)

// 查询视图
view := svc.View()
cells := view.Heatmap(start, end)
cells = view.QueryByNode(nodeID, start, end)
cells = view.QueryByPool(poolID, start, end)
cells = view.QueryByResource(resource, start, end)

// 指标
metrics := svc.Metrics()

// 修订记录
revisions := svc.Revisions()
```

## 持久化与恢复

- **预写日志（WAL）**：每个样本在处理前写入 WAL。
- **快照**：定期将已封口状态、修订记录、水位线写入快照。
- **恢复**：启动时加载快照，重放快照之后的 WAL 条目。已见样本集合用于去重，确保不重复计数。
