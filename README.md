# cluster-resource-heatmap-go

集群资源热力图数据服务：把逐节点资源采样按时间窗口聚合成可查询的热力图视图。
采样输入由内存管道模拟，整条链路只在本进程内运行，不依赖任何外部服务，结论可在本地稳定复现。

## 构建与运行

```bash
go build ./...
go test ./... -race          # 全部自动化测试（含竞态检测）
go run ./cmd/heatmapd -nodes 8 -rate 200 -data-dir /tmp/heatmap
```

`cmd/heatmapd` 是演示程序：在本进程内模拟节点采样上报（含乱序、迟到、重复），
周期性打印按节点池聚合的 CPU 热力图与运行指标。

## 架构

```
采样源(内存管道) --> [有界队列] --> run goroutine(单写者) --> 聚合引擎(可变状态)
                                        |                      |
                                        +-- WAL/快照落盘       +-- 原子发布不可变 Snapshot
查询 --> Service.Query --> 当前 Snapshot(只读, 多版本并发安全)
```

- **单写者**：所有状态变更都在唯一 run goroutine 内串行执行，无锁化；
- **多版本读**：每次处理后原子发布不可变 `Snapshot`，查询只读快照，
  任一时刻查询到的都是某个已提交的完整视图，慢查询不阻塞聚合推进；
- **持久化**：`wal.log`（已接受且未清理的采样）+ `snapshot.json`（已封口单元、修订、水位），
  均为原子重写（tmp+rename）。

## 窗口语义

- 窗口为半开区间 `[Start, End)`，起点对齐到 Unix 纪元的 `SlideStep` 整数倍；
- `SlideStep < WindowSize` 时为滑动窗口，一条采样可归属多个窗口；
  `SlideStep == WindowSize` 时为滚动窗口；
- 窗口归属只取决于 `(WindowSize, SlideStep, 事件时间)`，与到达顺序、并发度无关：
  相同输入（在补算期内到达）在任意到达顺序下产出的单元逐条一致
  （`Version` 除外，见修订规则）；
- 单元（Cell）= 一个窗口 × 一个节点 × 一种资源，聚合 `Count/Sum/Min/Max`，`Avg` 派生。

## 水位策略

- 水位 = 已见最大事件时间 − `AllowedLateness`，单调不减；
- 窗口 `End <= 水位` 时**封口**：从窗口内全量采样计算单元，版本置 1，标记 `Sealed=true`；
- 封口前的单元在快照中可见但标记 `Sealed=false`，与已封口状态明确区分；
- 窗口 `End + RevisionHorizon <= 水位` 时**清理**：丢弃原始采样与去重状态，
  已封口单元永久保留供查询；此后到达该窗口的采样被拒绝并计入 `TooLate` 指标
  （可观测，绝不静默丢弃）；
- 拒绝边界依赖水位推进时机，因此"任意顺序逐条一致"的保证适用于补算期内到达的采样。

## 去重与迟到

- 按 `SampleID` 全局去重：重复到达的采样绝不计入两次，计入 `Duplicates` 指标；
- 迟到但落在补算期内的采样：若窗口未封口则正常计入；若已封口则触发**修订**；
- 超出补算期的迟到：拒绝并计入 `TooLate`。

## 修订规则

- 已封口窗口收到补算期内的迟到采样时，用窗口内**全量**采样重算该单元，
  `Version +1`，并追加一条 `Revision` 记录（窗口、节点、资源、版本、原因、时间），可追溯；
- 修订是整单元替换，不存在只改部分字段的中间状态；
- 补算结果与用全量数据直接聚合的结果逐字段一致（有测试保证）；
- `Version` 记录修订次数，与到达历史相关；聚合内容（窗口/维度/Count/Sum/Min/Max/Sealed）
  与到达顺序无关。

## 查询与层级自洽

`Query{NodeID, Pool, Resource, From, To}` + `GroupBy{Node, Pool, Cluster}`：

- 时间范围按窗口起点过滤：`Start ∈ [From, To)`；
- 池级/集群级由节点级单元直接合并派生：`Count/Sum` 相加、`Min` 取小、`Max` 取大，
  任一层级与底层单元自洽，跨窗口、跨维度合并不重复计数、不漏计。

## 背压与资源上界

- 摄入队列容量固定（`QueueCapacity`），内存与待处理量有界；
- 队列满时 `Ingest` 立即返回 `ErrBackpressure` 并计入 `Rejected` 指标（确定且可观测）；
- `ctx` 取消/超时的摄入不会入队，不产生任何部分写入；
- 状态变更全部在单 goroutine 内完成，快照原子发布，不存在写一半的窗口。

## 持久化与重启恢复

- 每条已接受采样先落 WAL（`wal.log`，JSON 行，逐条 sync）；
- 封口/修订/检查点时原子重写 `snapshot.json`；
- 检查点压缩 WAL，仅保留未清理窗口的采样；
- 恢复流程：加载 `snapshot.json` → 重放 WAL →
  未清理窗口从采样重建（已封口的用全量采样重算、版本沿用快照值）→ 补做崩溃前来不及的封口；
- `SampleID` 去重使重放幂等：恢复后不重复计入、不丢失；
- 已封口窗口及其修订记录重启后完整还原，未封口中间态与已封口状态可区分。

## 配置项（`heatmap.Config`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `WindowSize` | 1m | 窗口长度 |
| `SlideStep` | =WindowSize | 滑动步长，小于窗口长度时为滑动窗口 |
| `AllowedLateness` | 0 | 水位宽限：水位 = 最大事件时间 − 该值 |
| `RevisionHorizon` | 0 | 封口后仍接受补算的时长，越过即清理 |
| `QueueCapacity` | 1024 | 摄入队列容量（背压上界） |
| `DataDir` | "" | 持久化目录，空为纯内存 |
| `SnapshotEvery` | 1s | 周期检查点间隔 |

## 测试覆盖

`internal/heatmap/*_test.go`：

- 窗口归属：滚动/滑动/边界半开确定性；
- 聚合：乱序洗牌 20 轮逐条一致、重复去重、封口、迟到补算与全量直算一致、
  超期拒绝、封口后无修订不变化；
- 查询：节点/池/集群层级自洽、时间范围过滤、空快照；
- 服务：背压拒绝与指标、取消不写入、并发查询与聚合的视图一致性（-race）、
  优雅重启恢复、崩溃（无检查点）恢复。
